> - OAuth authentication is intended for ordinary use of Claude Code and other native Anthropic applications. Third-party tools may not collect, store, or intermediate Claude.ai credentials or session tokens, and Anthropic may enforce this without prior notice. ([Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use))
>
> Using your subscription token this way may put your Claude account at risk. To check your usage, run `/usage` in Claude Code or open Settings → Usage on claude.ai.

# Ange

A macOS desktop widget (WidgetKit) that monitors Claude and Claude Fable subscription usage.

Forked from [dependentsign/ClaudeUsageWidget](https://github.com/dependentsign/ClaudeUsageWidget) with Codex support removed.

## Features

- **5-hour session usage** with progress bar
- **Weekly usage** with progress bar
- **Separate Fable weekly usage** with reset time
- **In-app dashboard** with manual refresh
- **Reset countdown** for both windows
- **Color-coded** green → yellow → orange → red
- **Three widget sizes** — small, medium, large
- **Dual auth** — OAuth token or session key
- **Auto-refresh** requested every 5 minutes; macOS controls actual scheduling
- **Original app icon** included under MIT, with no third-party icon assets

## Manual Setup

### 1. Build

```bash
git clone https://github.com/elbaph/ange.git
cd ange
open ClaudeUsageWidget.xcodeproj
```

In Xcode:
- Select your **Development Team** in both targets (ClaudeUsageWidget + ClaudeUsageWidgetExtension)
- Update **Bundle Identifier** if needed
- Build & Run (⌘R)

Alternatively, run `./scripts/build-local.sh` to produce `build/ange-1.1.zip`. It builds in a temporary directory to avoid Documents/iCloud metadata breaking code signing.

### 2. Configure Credentials

Enter and save credentials in the app, or create `~/.claude/claude-usage-widget.json`. Fable uses the same Claude credentials:

**Option A: OAuth Token (recommended)**
```json
{
  "oauthToken": "your-oauth-bearer-token"
}
```

**Option B: Session Key**
```json
{
  "sessionKey": "sk-ant-sid01-...",
  "organizationId": "your-org-uuid"
}
```

<details>
<summary>How to get session key</summary>

1. Open [claude.ai](https://claude.ai) and log in
2. DevTools (F12) → Application → Cookies → copy `sessionKey`
3. Get org ID:
```bash
curl -s https://claude.ai/api/organizations \
  -H "Cookie: sessionKey=YOUR_KEY" | python3 -m json.tool
```
Select the subscription organization you use and copy its **`uuid`**, not the numeric `id` or `parent_organization_uuid`.

</details>

Existing configuration remains compatible. `claudeEnabled` toggles Claude; legacy Codex fields are removed on save. Saves preserve unknown fields and write the file in place with owner-only permissions (`0600`); the sandbox only grants that exact path, so no temporary file is used.

### 3. Add Widget

1. Right-click desktop → **Edit Widgets...**
2. Search **"Claude"**
3. Choose size and add

## How It Works

The widget calls Claude's usage endpoint:

| Method | Endpoint |
|--------|----------|
| OAuth | `GET https://api.anthropic.com/api/oauth/usage` |
| Session Key | `GET https://claude.ai/api/organizations/{orgId}/usage` |

Returns:
- `five_hour.utilization` — 5-hour window usage %
- `five_hour.resets_at` — reset timestamp
- `seven_day.utilization` — weekly usage %
- `seven_day.resets_at` — weekly reset timestamp
- Fable: prefers Fable model entries with `weekly_scoped` in `limits[]`; supports `seven_day_overage_included` / `seven_day_fable` fallback

Percentages represent **usage consumed**. Missing data shows `—`, not 0%; Fable percentages are not rescaled by an inferred 50% allowance.

OAuth is tried first, then the session key. HTTP 401 prompts credential renewal, 403 prompts checking login and access, and 429 prompts waiting until the next refresh. Medium and large widgets include reset times; large includes the update timestamp. Subscription usage endpoints may change.

## Development

### Project Structure

```
ange/
├── ClaudeUsageWidget/                    # Host app (dashboard + configuration)
├── ClaudeUsageWidgetExtension/           # WidgetKit timeline and entry point
├── Shared/                              # Shared models, requests, and views
├── Tests/UsageCoreTests/                 # Regression tests
├── scripts/                             # Build, previews, icon generation, live checks
├── artwork/                             # Original icon SVG and license notes
└── screenshots/
```

> **Note:** Both the app and the widget extension run in App Sandbox with no ATS exceptions. The app may read/write, and the extension may only read, `~/.claude/claude-usage-widget.json` (temporary-exception entitlements). We use `getpwuid(getuid())` to resolve the real home directory instead of `FileManager.default.homeDirectoryForCurrentUser` (which returns the sandbox container path).

### Validation

```bash
swift test
./scripts/build-local.sh

# 18 SwiftUI previews: three sizes × light/dark × normal/error/missing data
mkdir -p build
swiftc Shared/UsageModels.swift Shared/UsageViews.swift scripts/RenderPreviews.swift -o build/render-previews
build/render-previews
```

`CheckLiveUsage.swift` optionally performs a read-only check using local credentials, printing only usage and errors. The icon is generated by `GenerateAppIcon.swift`; see [artwork](artwork/README.md) for provenance and licensing.
